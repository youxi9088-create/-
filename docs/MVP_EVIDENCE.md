## 阶段门禁记录

### 阶段一：核心玩法与初始 UI/UE

- 执行状态：已验证（2026-09-08 用户试玩反馈后重判并修复）。
- 被证据推翻的旧结论：旧 `runNpcTurns()` 把林星、米娅固定写成同时过牌，再立即 `ROUND_RESET`；截图中的 #4/#5/#6 证明那只是引导脚本，不是三人回合制主功能。此前“首局可玩”的结论已撤销，不再作为验收证据。
- 修复选择：服务端逐位 `advanceTurn`，基于每位 NPC 的实际手牌枚举单张、对子、三张、炸弹、顺子与王炸并做压制判定；玩家有合法的“不出”路径；两次连续不出才重置给最后出牌者。前端在每位 NPC 回合显示姓名、思考状态、禁用非当前回合手牌、桌面实际牌和出牌者。
- 竞品参考：参考《超真实麻将 Venus Returns》的桌面模式、新手自动推进与角色近景回合反馈，只采用“可见轮次、自动推进辅助、角色反应与桌面状态同屏”的交互原则；不采用其成人内容或奖惩逻辑。
- 证据：实际浏览器在默认 0.9 秒节奏下验证“你出 3♣ → 林星应答 → 米娅应答 → 你选择压制或不出”，中心区显示 `桌面牌型：单张 · 米娅已出` 与 `8♠`。Playwright 4/4 通过，其中完整主循环按浏览器 UI 的“提示 → 出牌/不出 → NPC 逐位决策”运行至 `ROUND_SETTLED`。
- 已验证目标：服务端创建局、叫分、合法/非法出牌、提示、逐位牌友真实决策、压制/不出、胜负、结算与刷新恢复。
- 已知风险：完整规则集尚未达到文档的 100+ fixture、随机 1000 局与 RLCard/DouZero 对照。

### 阶段二：表现与体验优化

- 执行状态：已验证（官方资产运行时 + 受控 UGC Mock 范围）。
- 证据：两位原创成年虚构 AI 牌友已接入大厅、牌桌、结算、写真馆；每位含 3×2 动作表（A01 待机、A02 出牌、A03 过牌、A04 胜利、A05 失败）与 idle/play/pass/win/lose 台词包。实际浏览器从 `http://127.0.0.1:4175` 走完首局，在独立 `#/table` 页面恢复同一序列号和手牌；回放弹层呈现“正在回放 · 胜利动作”。
- 已验证目标：两位官方牌友的视觉身份、运行时动作/台词、L1/L2 选择、结算四阶段、写真馆实际回放、可见焦点、字段级拒绝、减少动态偏好和深链导航。
- 资源规格：稳定 palId、auditRecordId、outfit、dance、完整 actionPack、五类 dialogue、fallback、图片 URL、3:4 肖像、动作表、alt 和来源记录均已定义。
- 自动化回归：`npm run verify` 通过（9/9 Node 测试，语法、构建和 fixture 全绿）；Playwright 3/3 通过，覆盖首局到写真馆、工坊策略/版本链与直接牌桌恢复。
- 不作为生产验收：真实视频主轨、四浏览器矩阵、全量规则/性能门禁和真实 UGC Provider 尚未验证；工坊仍明确显示 `MOCK PROVIDER` 与 `DEGRADED_READY`。

### 阶段三：一句话生成与资源流水线

- 执行状态：已实现待阶段三正式推进。
- 证据：Playwright 工坊路径验证了安全描述生成 `DEGRADED_READY`、确认建档和 PL-7 真人/名人输入拒绝；Node 测试验证 audit record 与成人虚构 Contract。
- 已验证目标：输入 → PalIntent → policy/audit → Mock asset → `DEGRADED_READY` → 确认建档 → Inspector 可追溯。
- 明确降级：真实 Provider 未授权时不调用外部服务；使用已审 Mock preset，公开标记其状态。

### 阶段四：UI / 交互硬化

- 执行状态：已验证（2026-09-12）。
- 被证据推翻的旧结论：`.table-felt` 的高度公式用了个手写魔数 `330px` 作为扣除项，而实测 1440×900 的真实占用是 945px —— **每档桌面分辨率都在纵向溢出**（1440×900 溢出 45px，1280×720 溢出 89px）。此前"牌桌布局已适配桌面"的结论已撤销。
- 修复选择：把 felt 高度改为从实测几何推导的 `clamp(310px, calc(100dvh - 313px - clamp(96px, 12dvh, 115px)), 720px)`，并让 `.hand` 与 `.table-felt` 共用同一个 `clamp` 表达式，消除两处数字各自漂移的可能。同步补上玩家侧的节奏控制（三档 NPC 速度）、结算跳过、Web Audio 合成音效与手牌命中区修正。
- 竞品参考：沿用阶段一确立的"可见轮次 + 角色反应与桌面状态同屏"原则；节奏控制参考单机棋牌的"速度档位"惯例，不引入联网或排行逻辑。
- 证据：1440×900 / 1440×800 / 1366×768 / 1280×720 / 1920×1080 / 2560×1440 六档实测**纵向溢出均为 0**。新增 7 条 Playwright 用例守护版面、命中区、速度持久化、音效状态、结算跳过与画廊 solo 布局；全套 **11/11 通过**，`npm test` 17/17 通过。
- 已验证目标：无纵向溢出的桌面版面、每张手牌都响应自己的点击、NPC 三档速度可调且持久化、结算可一键跳过演出、6 类事件音效（可静音且尊重减少动态偏好）、低卡池画廊居中放大。
- 已知风险：1280×720 下 `.opponent.top` 有约 2px 溢出（肉眼不可见）；两套样式表仍有 53 组同名选择器（深色主题整体推翻浅色底，属设计意图，本次刻意未合并）。
- 不作为生产验收：音效为代码合成，未做混音/音量控制与真机听感验证；四浏览器矩阵仍未覆盖。详见 `docs/UI_P0_CHANGELOG.md`。

## 修正条件

- 若真实试玩中存在点击失效、牌型显示不一致、结算不同步或视觉状态遮挡，先记录精确状态与事件序列，再定位输入、规则、布局或状态根因；修复后重跑本路径和不回归基线。
- 若 RLCard/DouZero 兼容探针、真实 Provider 或上线环境引入差异，需重新判断而不是把当前 Mock 验证外推为生产验收。
