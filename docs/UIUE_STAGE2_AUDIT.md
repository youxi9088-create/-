# 阶段二 UI/UE 风格检查与复验

检查基准：`game-mvp-evidence-loop` 的阶段二门禁，以及 `web-design-guidelines`（2026-09-08 拉取）。范围：`apps/web/index.html`、`apps/web/app.js`、`apps/web/styles.css`、`apps/web/styles-overrides.css`。

## 检查结论与修正

| 检查项 | 检查结论 | 修正与证据 |
| --- | --- | --- |
| 角色样本与风格层级 | 原先只有 CSS 头像，无法验证“牌友身份—演出—写真”视觉连续性。 | 接入林星与米娅两张 3:4 原创成年虚构 AI 肖像及各自 3×2 动作表。大厅、牌桌、结算、写真馆复用同一身份；A01–A05 在待机、出牌、过牌、胜利、失败状态切换，均有稳定路径、alt、审计记录和来源说明。 |
| 1280×720 核心信息可见性 | 原先 20 张手牌需横向滚动，末张被截断。 | `styles-overrides.css` 在目标桌面宽度收紧牌宽和叠放。E2E 断言 `scrollWidth - clientWidth <= 1`，并保留 `first-loop-table.png`。 |
| 导航与状态 | 原先为按钮导航，URL 不反映页面。 | 改为 hash 深链链接；Playwright 验证 `#/workshop`。 |

| 工坊反馈 | 原先 PL-7 仅 Toast 告知。 | 改为输入框旁 inline error、`aria-invalid`、`role=alert`，拒绝时焦点回到字段。 |
| 动效与偏好 | 原先舞动不支持减少动态。 | `prefers-reduced-motion` 下关闭演出动画；Playwright 断言 `animation-name: none`。 |

## 阶段二门禁结论

在当前“官方 AI 资产运行时 + 受控 UGC Mock”的授权边界内，阶段二通过：两套成年虚构角色形象、五态动作包和五类台词包已经接入，核心玩家路径与独立页面恢复均复验通过，阶段一基线没有回归，资源规格可复用。

### 试玩反馈后的回合交互复验（2026-09-08）

- 原问题：玩家出牌后，两个 NPC 被服务端同步写死为过牌，界面立即显示“等待本轮首出”。这使桌面状态、事件流和玩家的下一次操作失去因果关系。
- 修复：改为逐位权威回合；桌面持续展示当前牌型、实际牌面与出牌者；NPC 思考时禁用玩家手牌并显示角色名；玩家面对可压制牌型时获得“提示 / 不出 / 出牌”。
- 结果：默认节奏的实际浏览器截图显示 `3♣ → 林星实际出牌 → 米娅实际出牌 8♠ → 玩家压制或不出`。Playwright 增加完整终局用例，浏览器 UI 在加速测试时钟下到达 `ROUND_SETTLED`；4/4 用例通过。
- UI/UE 判断：采用竞品的“桌面模式、自动推进辅助、角色回合反馈”原则，而非复制其成人主题或内容。`等待本轮首出` 现在只在当前领出者尚未出牌时出现。

未外推为 V1.1 的生产验收：真实视频主轨、四浏览器矩阵、RLCard/DouZero、全量规则/性能门禁和真实 Provider 仍未验证。

### 场景化首页与牌桌重构复验（2026-09-08）

- 输入：试玩反馈指出原页面更像通用后台，缺少“进入牌局”的情绪、人物演出与桌面空间感。
- 参考边界：只提取桌面模式、自动回合辅助、关键回合的镜头/角色反馈等交互原则；不复制竞品的成人内容、素材或品牌表达。
- 实施：大厅改为单一主入口的月夜会所场景；牌桌改为居中桌面、局分 HUD、左右牌友位置、中心待压制牌和底部手牌操作层。角色每次真实出牌会同步显示动作帧与台词泡泡。
- 实际浏览器复验：新标签进入 `#/table`，叫 3 分后出 `3♣`；观察到 `林星出 4♦ → 米娅出 8♠ → 玩家获得 提示 / 不出 / 出牌`，手牌从 20 变为 19，事件流同步记录三次真实动作。
- 视觉判断：1440px 截图中主操作为金色“出牌”，次操作为深色描边“提示 / 不出”；桌面、手牌和事件流有清晰的三层阅读顺序，未出现横向溢出。

### 试玩反馈后的实体出牌区复验（2026-09-08）

- 原问题：出牌结果只以“牌型 + 牌面文本”停留在桌面中间，并混入 RuleEngine、序列号与事件码；这既不符合牌桌的视觉语法，也把调试信息暴露给玩家。
- 修复：当前可压制牌改为实际的牌面扇形，按最后出牌者显示其牌型与出牌者；轮到谁、可压制/不出成为独立的即时回合提示。移除玩家界面的权威引擎、序列号和事件类型，只保留简洁的牌局记录；原始审计信息仍可在检查器查看。
- 验收：浏览器路径保持“叫 3 分 → 玩家出牌 → 两位 AI 逐位决策 → 玩家压制或不出”；E2E 增加米娅出牌区的实体牌面断言。

### 用户提供视频资产接入（2026-09-08）

- 输入：`角色五态包` 含林星 A01–A05 原始 WebM、林星/米娅出场 MP4，以及米娅 A01 WebM。
- 决策：按用户指示直接使用原始 WebM，不进行抠像或转码；林星五态以同一 A01–A05 动作合同进入牌桌和结算，米娅只对 A01 使用视频，其余状态保留原动作表回退。
- 流程：点击“进入今晚牌局”播放两位牌友的出场 MP4（可跳过）；游戏事件的 A02/A03/A04/A05 将直接切换到林星对应 WebM，结算与写真回放复用 A04。

### 试玩反馈后的随机发牌复验（2026-09-08）

- 原问题：`GameService.newGame()` 使用固定的玩家手牌和固定切片的两家 NPC 手牌，因而每一局实际都是同一副牌；这违背斗地主的核心重复游玩预期。
- 修复：每局由服务端生成独立 32 位洗牌种子，以 Fisher–Yates 洗完整 54 张牌；叫分前三家各 17 张，叫 3 分后玩家作为地主领取 3 张底牌变为 20 张。种子仅保留在服务端局对象，事件仅记录不可逆的 `dealRef`，不会向玩家暴露全局牌堆。
- 不回归：牌型判定、提示、逐位 AI 回合、幂等命令与结算路径不变；浏览器用例不再假设某一张固定牌或 NPC 必然打出固定牌。
- 证据：单元测试验证 54 张无重复、不同种子牌序不同、叫分前 17 / 叫分后 20 张；Playwright 4/4 通过。真实浏览器连续开两局的初始手牌分别为 `3♣ 3♥ 4♦ … K♦` 与 `3♣ 4♦ 5♠ … SJ`，已确认不同。

### 试玩反馈后的结算视频容器复验（2026-09-08）

- 原问题：结算页沿用了牌桌头像的 `78×94` 容器来承载 A04/A05；在 `DESTINATION` 阶段，视频被缩成一张静态头像，玩家无法看见动作内容。
- 修复：结算层改为独立的全幅 `settlement-video-frame`，直接挂载林星 A04/A05 WebM，并使用循环播放、视频状态标题与不遮挡画面的底部说明。`PERFORMANCE` 绑定 A04，`DESTINATION` 绑定 A05。
- 验收：浏览器主流程打到结算后，自动点击三段结算操作；断言视频可见、宽度大于 300px、A04/A05 源文件分别正确，并保存 `test-results/settlement-video-performance.png` 与 `test-results/settlement-video-destination.png`。截图复核确认动作视频占据结算舞台，而非头像位。

### 试玩反馈后的无边框结算窗口复验（2026-09-08）

- 原问题：即便视频已可见，结算外层仍是大块白色卡片，视频只占中部；这削弱了结算动作的沉浸感，也与用户要求的“无边框视频窗口”不符。
- 修复：采用无边框视频 Lightbox。移除白色卡片背景与外侧说明区，窗口宽度提升至最多 980px；阶段标题、动作标识、说明与操作按钮均叠加于视频的深色安全区内。
- UI/UE 检查：保留对话框语义、初始焦点、可见按钮、文本对比和暗色遮罩；不使用图标替代文字按钮，避免失去“重开一局 / 打开写真馆”的明确去向。
- 验收：Playwright 断言结算视频宽度大于 700px、外层背景透明、底部操作区可见；查看 `test-results/settlement-video-destination.png`，确认 1440px 截图中没有视频外白色区域。
