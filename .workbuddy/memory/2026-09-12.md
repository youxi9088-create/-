**关键技术结论（复用价值高）**
1. **felt 高度公式**：`clamp(310px, calc(100dvh - 313px - clamp(96px, 12dvh, 115px)), 720px)`。313 = topbar68 + pad18/28 + side30 + gap28 + feed52 + hand-wrap-margin12 + handWrap常数77 的合并项。**让 `.hand` 与 `.table-felt` 共用同一个 clamp 表达式**是关键——避免两处数字漂移。六档分辨率实测溢出均为 0。
2. **CSS 死类判定必须用真实 DOM 采集**，不能静态 grep。`band-N`/`lv-N`/`from-*`/`card`/`red`/`selected`/`off`/`loading`/`empty` 全是模板字符串拼接。已把 KEEP 白名单写进 `prune-dead-css.mjs`。本次确证可删 21 个唯一类（不是首轮报的 32 个）。
3. **手牌负 margin 方向**：必须从右侧改左侧（`.card + .card { margin-left: N }`），配合 `justify-content: flex-start`。否则横向溢出时 flex 行会重居中，吃掉最左卡的命中区。
4. **Playwright 状态泄漏**：该 API 的牌局/画廊状态存进程内存，`reuseExistingServer: true` 会让上一轮的写真卡泄漏进下一轮，导致断言依赖执行顺序（`first-loop` 单跑过、全套挂）。已改 false。
5. **沙箱限制**：`npx playwright test` 默认 `--output=test-results` 会触发 safe-delete bulk guard（>50 文件即拒）。需用 `--output=tr-<ts>`，且该目录事后需人工清理。`rm -rf` 大目录同样被拒，别在脚本里做大规模删除。

## 追加 2：出牌落点定位修复（用户报"拍的位置都很奇怪"，选 A 方案）

**问题**：AI 出牌悬在另一名角色身上，三个标签（牌型/牌/已出）分属三套锚点。

**根因（实测确认，不是猜测）**：
1. `.opponent.*` 座位靠 `top/right/left` 百分比挂边，`.from-*` 出牌锚是**完全独立的硬编码**，两者无共享坐标系。
2. `.from-pal-linxing { top: 296px }` 写死在 310px 的 felt 里 → 必然贴近底部。
3. `.pal-bubble` 是座位 flex 行的**末位子元素**，`left: calc(100% + 8px)` 量的是整行而非立绘。
4. `.play-stage { z-index: 4 }` 高于座位 `z-index: 2` → 出牌区物理上画在人身上。

**关键实测数据（1440×900，felt 1325px）**：
| 元素 | 占位 |
|---|---|
| 林星立绘 | x556–792（中心 674） |
| 米娅立绘 | x979–1215（中心 1097） |
| 两者间隙 | x792–979，中点 885.5 |
| `.opponent.top` 整行 | 341px = 立绘236 + gap12 + 角色chip76 + gap12 + 背面牌5 |

**修法**（`styles-overrides.css` 末尾"round 4"块，单一真源）：
- `.opponent.top` 加 `translateX(calc(-50% + 52.5px))`，把立绘从"行居中"修正到真正居中。52.5 = (76+12+5+12)/2。**不要手调这个数**——背面牌 `▣ ▣ ▣` 在某些字体下只有 5px 宽，试凑必过头。
- `.from-pal-mia { left: calc(50% + 17%) }`：落在两角色间隙中点。
- `.from-player { left: 30% }`（短视口 27%）：40% 会压到林星左缘 556。
- `@media (max-height: 780px)`：座位缩到 176/192px，felt 下限放到 300px，解决 1280×720/1366×768 滚动。

**六档视口实测**：1024×720 边界退化(30px 滚动) · **1280×720 PASS** · 1366×768 PASS · 1440×900 PASS · 1920×1080 仅居中差 12px · 2560×1440 PASS。

### 血泪教训（高复用价值）
1. **别试凑 CSS 常量**。本轮我连续试错 4 次（72px→52.5px、34%→17%、40%→30%），每次都"看起来有改善"。正确做法是先用 headless 脚本 dump 出兄弟元素实际宽度和 felt 宽度，再**算出**百分比。`52.5` 这种数必须写注释说明推导。
2. **`object-position` 会骗过几何断言**。`.pal-standee { overflow:hidden }` + `img { object-position: 56% center }` 使 img 的 bounding box 比盒子右偏 ~12px。断言"角色居中"必须量**盒子**不是**img**，否则正确布局也会失败。
3. **`reuseExistingServer: false` 是按文件隔离，不是按用例**。新加的用例若中途出牌，会污染同文件后续用例的手牌数（实测 expected 20 got 17）。**会改状态的用例必须放文件末尾**并注明原因。
4. **断言时机要等状态稳定**。`.played-stack` 一出现就量，会抓到 `from-player`→`from-pal-mia` 的中间态。用 `waitForFunction` 等 owner 类落定再量。
5. **百分比宽度会翻转绝对定位元素**。给 `.opponent.right` 的子元素设 `width:20%`（相对 felt 解析）会让 flex 行撑破盒子，米娅整个跑到桌子左边。右侧锚定的元素**只能固定像素宽**。
6. `testMatch: /.*\.mjs/` 必须在独立截图配置里显式写，Playwright 默认只认 `*.spec.*`/`*.test.*`。
